01 · Project Description

What is NeuroDrive?

A 3D soccer car game built in Unity — where you race a real sport car inside a neon stadium and score goals with a physics-based soccer ball.

The Product

What is NeuroDrive?

🏎️

Soccer Car Game

NeuroDrive is a 3D physics-based soccer car game made in Unity 6. You drive a real sport car model around an indoor stadium and hit a soccer ball into the goal. Think Rocket League — but built by 9th graders from scratch.

⚽

Goal-Based Gameplay

The objective is simple: use your car to push the soccer ball into the opponent's goal. A score counter tracks successful goals. Each scored goal resets the ball to the center of the field.

🌟

Fully Designed World

The stadium is a fully imported 3D model with neon hex-wall materials, real football field markings, crowd seating, and scoreboard screens — all running in Unity's Universal Render Pipeline (URP).

The Problem

What Problem Does It Solve?

Most student game projects stop at a basic scene with primitive shapes and keyboard input. NeuroDrive goes further — it demonstrates a full production pipeline: real 3D assets, physics-based car mechanics, a proper goal detection system, neon URP materials, aerial boost scripting, and wall-riding. It proves that high-school students can ship a polished, playable game.

What Makes It Unique

Key Differentiators

🚀

Aerial Boost System

Press Shift to activate the boost. The car accelerates forward using force on the Rigidbody, the camera FOV widens for dramatic effect, and a boost audio clip fires — all implemented in C#.

🧲

Wall-Riding Physics

A Raycast checks the surface below the car. On a wall, AddForce pushes the car into the surface and Quaternion.Slerp rotates it to align — letting the car stick to and drive along walls.

🥅

Goal Detection & Scoring

A trigger collider behind each goal detects when the Ball enters. The score counter increments, the ball is deactivated, and the scene reloads after a short delay — a full goal cycle.

🏟️

Pro 3D Stadium

The Grant Stadium asset provides a full octagonal arena with realistic architecture. Real football field markings, corner flags, screens, and gates — not primitive cubes.

02 · Full Functionality

How NeuroDrive Works

A complete breakdown of the game loop — from booting the game to scoring a goal and replaying.

Step-by-Step Game Loop

User Flow

Step 01 — Launch

Game Loads in Unity

The scene initialises with the stadium, car, soccer ball, goal triggers, and the HUD canvas. Score = 0. The camera is parented to the car in a third-person follow position.

Step 02 — Drive

Player Controls the Car

WASD or arrow keys control acceleration, braking, and steering through the New Input System. The sport car model moves with Rigidbody physics — weight, friction, and torque all apply.

Step 03 — Boost

Hold Shift to Activate Aerial Boost

Left Shift fires rb.AddForce(transform.forward * boostPower). The camera FOV lerps from 60° to 80°, creating a speed rush effect. Audio plays while held, stops on release.

Step 04 — Score

Hit the Ball into the Goal

Drive into the soccer ball to push it. When the ball enters the goal trigger zone, globalScore++ fires, the HUD updates, the ball deactivates, and the level restarts after 1 second.

Step 05 — Repeat

Scene Reloads — Play Again

The scene reloads via SceneManager.LoadScene but the score persists using a DontDestroyOnLoad object, so the count carries over between rounds.

System Architecture

How The Layers Connect

🏎️

Game Layer — Unity + C#

Unity handles all 3D rendering at runtime. C# scripts process New Input System events every FixedUpdate frame — applying forces to the Rigidbody, rotating the car, detecting goal triggers, and updating the HUD text.

💾

Score Persistence

A DontDestroyOnLoad GameObject stores the global score. When a goal is scored and the scene reloads, this object survives and passes the updated count to the new HUD instance.

🎨

Render Pipeline

Universal Render Pipeline (URP) enables high-quality lit shaders, emission maps for neon walls, and post-processing effects like bloom and colour grading — impossible with the default legacy pipeline.

05 · Sponsor Interview

Sponsor Interview

We conducted a full interview with our project sponsor — a university student in education and technology — to validate NeuroDrive's concept and gather real feedback.

📅 March 2025
📍 In-person
⏱ ~30 minutes

Key Questions & Answers

Interview Highlights

Q — Why is this type of project important for teenagers?

Because teenagers shape the future of society, and unresolved issues — including lack of engaging, educational tools — can negatively affect their education, well-being, and social behaviour. A game that is both fun and purposeful addresses this gap directly.

Q — What do you think about a soccer car game as a school project?

It demonstrates real technical ambition. Building physics-based car controls, a working goal system, and a proper 3D environment in Unity shows commitment that goes far beyond a typical school project prototype.

Q — What would make NeuroDrive more engaging for players?

Multiplayer — even local split-screen — would dramatically increase the fun factor. Competitive play is a huge driver of engagement. Adding a proper main menu and match timer would also make it feel more complete as a product.

Q — What feedback would you give on the current build?

The car physics feel satisfying with the boost, but mid-air control needs work — once the car leaves the ground it becomes hard to steer. Implementing a stabilisation system that corrects the car's rotation in mid-air would massively improve playability.

Q — Would you fund this if it were a Kickstarter?

For a project built by two ninth-graders in seven weeks — absolutely. The scope is impressive and the technical execution is solid. With a proper main menu, multiplayer, and polished visuals, this could be a competitive indie release.

Code Snippet — Aerial Boost System

C# — Unity 6 CarBoost.cs 
using UnityEngine;
using UnityEngine.InputSystem;

public class CarBoost : MonoBehaviour
{
    [Header("Настройки физики")]
    public float boostPower = 15f;
    private Rigidbody rb;

    [Header("Настройки Камеры")]
    public Camera mainCamera;
    public float normalFOV = 60f;
    public float boostFOV  = 80f;
    public float transitionSpeed = 5f;

    [Header("Настройки Звука")]
    private AudioSource audioSource;

    void Start()
    {
        rb = GetComponent<Rigidbody>();
        if (rb == null) rb = GetComponentInChildren<Rigidbody>();

        // Авто-поиск камеры, если не перетащили в инспекторе
        if (mainCamera == null) mainCamera = Camera.main;

        // Ищем компонент звука на машине
        audioSource = GetComponent<AudioSource>();
    }

    void FixedUpdate()
    {
        if (rb == null) return;

        // Проверка нажатия Shift (New Input System)
        bool isPressed = Keyboard.current != null
                      && Keyboard.current.leftShiftKey.isPressed;

        if (isPressed)
        {
            // Ускорение
            rb.AddForce(transform.forward * boostPower, ForceMode.VelocityChange);

            // Эффект отдаления камеры (FOV)
            if (mainCamera != null)
                mainCamera.fieldOfView = Mathf.Lerp(
                    mainCamera.fieldOfView, boostFOV,
                    Time.deltaTime * transitionSpeed);

            // Включаем звук, если он есть
            if (audioSource != null && !audioSource.isPlaying)
                audioSource.Play();
        }
        else
        {
            // Плавный возврат камеры в норму
            if (mainCamera != null)
                mainCamera.fieldOfView = Mathf.Lerp(
                    mainCamera.fieldOfView, normalFOV,
                    Time.deltaTime * transitionSpeed);

            if (audioSource != null && audioSource.isPlaying)
                audioSource.Stop();
        }
    }
}

Block 04

Final Reflection

🔺

What Improved Most

Transitioning from basic arcade driving to physics that relies on mathematical vectors and surface normals. Paired with a complete graphical overhaul — from untextured primitives to a fully lit URP scene with neon emission materials — the game changed fundamentally in both feel and visual identity.

💬

Most Useful Feedback

Complaints about mid-air controls from beta testers forced the implementation of a dedicated stabilisation system — using Slerp-based rotation correction and the aerial boost mechanic. This single change drastically improved gameplay feel and made the car far more controllable during jumps.

🚀

Still to Improve

Optimising the nitro (energy cube) spawn system for fairer distribution across the field. Adding multiplayer — either local split-screen or online — is the primary planned feature for the next development cycle.
